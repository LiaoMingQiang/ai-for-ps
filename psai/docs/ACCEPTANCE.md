# 真机验收清单

这份清单要在**真实的 Photoshop** 里执行。自动化测试已经覆盖了 Helper、作业引擎、
Provider 协议和内置工作流（见下方「已自动化的部分」），但下面这些只能在实机上验证：
UXP 面板能不能加载、图层能不能取出来、结果能不能写回正确的位置。

## 已自动化的部分（不需要人工重跑）

```bash
npm run check                  # 三包 typecheck + lint + manifest 校验
npm test                       # 157 项：契约、Helper 集成、重启恢复、内置工作流静态校验、
                               #         云端预设自洽性、**全部 17 个功能的页面渲染冒烟**
npm run test:comfy:real        # 28 项：对真实 ComfyUI 的适配器端到端
npm run test:workflows:real    # 11 个固定功能逐个真实出图
npm run verify:rh              # 对着真实 RunningHub 接口核对 13 条云端预设的每一条绑定
npm run test:cloud:real        # 云端端到端：13 条预设逐个真出图 + 视觉裁判判提示词是否到位
```

这些覆盖了：作业状态机、并发闸、重启恢复不重提交、写回失败与 AI 失败分离、
DPAPI 密钥不外泄、工作流扫描与版本化、依赖预检、参数注入、11 份内置工作流真实出图、
13 条云端预设的节点绑定、云端提交/进度/结果/错误处理全链路。

### 页面渲染冒烟为什么单列一条

生成页曾经在 Photoshop 里整页白屏，原因是代码调了 `Element.toggleAttribute` ——
浏览器有、jsdom 有、UXP 没有。typecheck 过、lint 过、bundle 也构建成功，
只有装进 Photoshop 点开那一页才炸。

现在 `packages/plugin/test/uxp-dom.mjs` 提供的是一个**只实现 UXP 确实有的 API** 的 DOM，
`pages.test.mjs` 在它上面把 17 个功能的生成页以及历史/设置/ComfyUI Web 页各渲染一遍。
碰了 UXP 没有的东西就当场抛，CI 就能在进 Photoshop 之前拦住。
这不能替代真机验收（写回、取图层仍然只能在 PS 里验），但白屏这一类已经挡在门外了。

### 云端预设的门禁为什么要钉死种子

「提示词生效」这一项曾经时绿时红：同一份输入、同一句「红苹果」，
这次画苹果、下次画个红杯子 —— 管线完全正常，只是扩散模型本来就是随机的。
一个时好时坏的门禁比没有门禁更糟，它会训练人把红色当噪音忽略掉。

所以做了两件事：种子钉死（只能钉住主采样器，工作流里第二个 KSampler 或随机节点绑不到，
不是逐像素可复现，但最大的变量摁住了），以及判词只问「这张图讲的是不是那件事」，
不问「每个形容词都对上了吗」。真正要抓的失败长得很不一样 —— 提示词被吞成空串之后，
Flux 画出来的是文字截图、代码编辑器界面这类和输入毫无关系的东西，一眼就能判 NO。

### 云端"假成功"为什么必须靠看图

云端工作流跑通了、状态机走完了、图也下载回来了 —— 图却和提示词毫无关系。
这种情况真实发生过两次：一次是空 `nodeInfoList` 让云端拿作者的示例图出图，
一次是 `ArgosTranslateTextNode` 在 RunningHub 上不工作、把提示词吞成空串。
两次都是所有接口断言全绿。

所以 `test:cloud:real` 里加了一个**视觉裁判**：把结果图和「应该看到什么」一起发给
已配置的 Comfly 视觉模型，让它回 YES / NO。这是用真实接口做的语义断言。
换过云端预设之后，这一项必须重跑。
